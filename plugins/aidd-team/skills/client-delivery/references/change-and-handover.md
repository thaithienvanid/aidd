# Change orders, acceptance, and handover

Load this when you draft a change order, set up acceptance, or prepare the handover.

## A change order

- Each change order states its effect on scope, date, price, and risk, and the client tasks it adds.
- A client task that slips is a RAID issue. When it moves a date, it becomes a change order, never silent slack.
- The price and the client's decision are a person's. An agent drafts the order from the facts.

## Acceptance

- The contract names how many days the client has to accept a milestone, and what happens when they say nothing.
- Each milestone lists the Acceptance ids it covers, so the client tests against the same lines the gate checked.

## Handover

- Each account the product needs, such as a domain, a cloud account, or a store listing, is in the client's name before handover.
- Once the client holds each credential, remove the team's and every agent's access, and rotate each secret the team saw.
- Name each credential with where it now lives, never the secret itself.
- The warranty start is a date in the acceptance record.
