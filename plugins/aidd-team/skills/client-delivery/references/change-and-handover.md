# Change orders, acceptance, and handover

Load this when you draft a change order, set up acceptance, or prepare the handover.

## A change order

- Each change order states its effect on scope, date, price, and risk, and the client tasks it adds.
- A client task that slips is a RAID issue. When it moves a date, it becomes a change order, never silent slack.
- The price and the client's decision are a person's. An agent drafts the order from the facts.

## Acceptance

- The contract names how many days the client has to accept a phase, and what happens when they say nothing.
- Each phase lists the Acceptance ids it covers, so the client tests against the same lines the tests check.

## Handover

- Each account the product needs, such as a domain, a cloud account, or a store listing, is in the client's name before handover.
- Once the client holds each credential, remove the team's and every agent's access, and rotate each secret the team saw.
- Name each credential with where it now lives, never the secret itself.
- The warranty start is a date in the acceptance record.
- The repository row says what the client receives. With two repositories, the client already holds the product's repository, and the firm's home repository stays with the firm. With one, the history holds the proposal's budget and amounts. A person decides how the client gets the code without them, such as a copy of the product's folders, and records the choice in the row.
- The licence row lists each third-party component's licence. The contract says the repository lists them, so the row names where that list is and when it was checked.
- The vendor row adds the services the agents used, a model provider included. Each account moves to the client's name or closes, and the vendor register shows it.
- The client's data goes back to the client. Then it is deleted from the team's systems and every agent's storage, unless the client asks in writing to keep it. A person records the date.
- The agent setup row says what stays of aidd and the agents, and what is removed. Every agent's access and key ends, and each secret the agents saw is rotated.
- The decision row asks whether the client keeps aidd. If it does, the client's named approvers replace the firm's in `owners.approvers`, and any delegation the firm held ends, so every ask after handover goes to the client's people. If it does not, the client names its own rule for who decides a change, merges it, and releases it. A person records the answer from the client's own words.
