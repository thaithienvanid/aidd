# Extending a role

A role's capabilities are open-ended. Any skill, plugin, MCP server, or tool the harness can load extends it, on top of the domain packs. Each agent file lists starting points. They include a design-craft skill for the product designer, a browser for the verifier, static analysis for the security engineer, and a tracker for the product manager. A team adds its own the same way. Every one is optional. A role uses an extension only when the project already has it connected, and works from git and the repository's files when it does not. None of them is an instruction to adopt a service. Three rules keep an extension safe:

**Contents**

1. **Verify and pin.** It is third-party code that runs with the agent's permissions. Verify it and pin it by version or commit, and read its license and any note beside it before installing. **Tier** says who made it: `official` only when the harness vendor did. An entry the vendor's official directory lists (`listed_in`) keeps its maker's tier.
2. **Install through a change.** `.claude/**`, `.mcp.json`, and `AGENTS.md` are protected paths, so the gate makes it major and the security pool reviews it.
3. **Never widen, never decide.** It never widens a role's write area or decides a gate, because every subagent inherits the loop contract.

Record what is installed in `AGENTS.md`, so every role knows what it may use.

**Can** says what each extension itself can touch, read from its own source and docs:

- `network`: calls beyond the model API.
- `writes repo`: creates, changes, or deletes files in the repository, locally or through an API.
- `runs commands`: shell commands or other programs.
- `reads secrets`: needs a credential or can read one.
- `telemetry`: usage data sent to its vendor, and whether it can be turned off.

`read-only` means it only guides the agent, or only reads. Where the source did not settle one, the entry lists it anyway. A team reads this before it installs, not after. The change that wires an extension in touches a protected path, so the gate makes it major. The security engineer reviews it, and the human reviewer from the security pool approves it. That review looks hardest at `writes repo`, `runs commands`, and `reads secrets`: what the extension runs, with which credentials, and whether the pin is exact.
