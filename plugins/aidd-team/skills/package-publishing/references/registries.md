# Registries: the package-publishing detail

Each row was read at its source on 2026-09-30, and the npm and CocoaPods rows on 2026-10-22. A registry changes these
rules often. In Specify, re-read a row's source when it is more than six months old. Propose a changed row to aidd's
`schemas/packs.json` and this file together.

## Trusted publishing and provenance

| Registry | Trusted publishing (OIDC) from | Provenance | Lock it down | Source |
| --- | --- | --- | --- | --- |
| npm | GitHub Actions (GitHub-hosted runners), GitLab.com shared runners, CircleCI cloud; npm CLI 11.5.1 or later, Node 22.14.0 or later | generated by default from GitHub Actions or GitLab for a public package built in a public repository; none from CircleCI or a private repository; `npm audit signatures` verifies it on install | "Require two-factor authentication and disallow tokens" once the trusted publisher works; `npm stage publish` holds a release until a maintainer approves it with 2FA (npm CLI 11.15.0 or later), also from trusted publishing | <https://docs.npmjs.com/trusted-publishers> |
| PyPI | GitHub Actions, GitLab CI/CD, Google Cloud, ActiveState; the minted token lives 15 minutes | PEP 740 attestations, uploaded by default by `pypa/gh-action-pypi-publish` (GitHub Actions, GitLab CI/CD, Google Cloud) | remove the project's API tokens; yank, never re-upload, a bad file | <https://docs.pypi.org/trusted-publishers/>, <https://docs.pypi.org/attestations/producing-attestations/> |
| crates.io | GitHub Actions and GitLab.com (not self-hosted GitLab) | none from the registry; attest in CI | "Trusted Publishing only" mode in the crate settings disables API-token publishing | <https://blog.rust-lang.org/2026/01/21/crates-io-development-update/> |
| RubyGems | GitHub Actions | none from the registry; attest in CI | no API key stored once the trusted publisher works | <https://guides.rubygems.org/trusted-publishing/> |
| NuGet | GitHub Actions, through `NuGet/login` exchanging the OIDC token for a short-lived API key | none from the registry; attest in CI | delete the long-lived API keys | <https://learn.microsoft.com/en-us/nuget/nuget-org/trusted-publishing> |
| Maven Central | not a trusted-publishing registry in OpenSSF's December 2025 list | the `.asc` signature on every file | the Central Portal credential held only by the release job | <https://repos.openssf.org/trusted-publishers-for-all-package-repositories> |
| Homebrew | homebrew/core builds the bottles itself; a project's own tap is its repository | Homebrew's centralized builds | nothing to publish from the project | <https://docs.brew.sh/Acceptable-Formulae> |

"Attest in CI" is a GitHub artifact attestation (`actions/attest-build-provenance`, verified with
`gh attestation verify`) or SLSA provenance signed with Sigstore, published beside the release.

## What the registry refuses

| Registry | Required before it accepts the release | Source |
| --- | --- | --- |
| Maven Central | for every `<artifactId>-<version>.jar`, a `-sources.jar` and a `-javadoc.jar`; `.md5` and `.sha1` for every file; a `.asc` GPG/PGP signature for every file; POM `name`, `description`, `url`, `licenses`, `developers`, and `scm` | <https://central.sonatype.org/publish/requirements/> |
| Homebrew | homebrew/core only: open source under a DFSG-compatible licence, built from source (or portable output), a stable release with an immutable tag, no self-update, no downstream-only patch, vendoring only when the system dependency cannot work; builds and tests on Homebrew's CI matrix | <https://docs.brew.sh/Acceptable-Formulae> |
| npm, PyPI, crates.io, RubyGems, NuGet | a version is never overwritten: publish a new one, then deprecate or yank the bad one | each registry's documentation |
| CocoaPods trunk | nothing after 2026-12-02, when trunk stops taking new Podspecs for good (after a test run in early November 2026); ship new versions of an iOS library through Swift Package Manager | <https://blog.cocoapods.org/CocoaPods-Specs-Repo/> |

## The open-source steward (EU CRA, Art. 24)

A legal person that supports, on a sustained basis, free and open-source software intended for commercial
activities is a steward. A steward keeps a documented cybersecurity policy for secure development and vulnerability
handling, and cooperates with market surveillance authorities. It reports actively exploited vulnerabilities and
severe incidents from 2027-12-11, while a manufacturer's reporting started on 2026-09-11. It is not subject to
administrative fines. The reporting clocks are
`aidd-team:incident-response`'s. Source: <https://digital-strategy.ec.europa.eu/en/policies/cra-open-source>.
